# Edge cases: students, classes and groups over time

> Part of the Sodiq School platform spec, baseline of 3 October 2026 (document revision 88).
> Index and reading order: `docs/spec/00-index.md`. Where an edge-case file is more specific than a module file, the edge-case file applies.

| Case | Rule |
| --- | --- |
| A student joins 7 Oxford, which is split for English and feeds the mathematics groups. Nobody places him in a group. | A class membership cannot be saved without a group for every split or group subject of that class, from the same date. Bulk placement puts students into the smallest suitable group and tags them "placed automatically, review"; an import will do the same when one is added. |
| A student is enrolled in August before classes are formed. | An active student with no class is allowed only before their start date. They appear with class "—", under a "No class" filter and in a counter on the Academic Vice Principal's home page, and are in no journal. |
| A class is full. | The maximum size is a hard limit on the effective date, counting scheduled joins and leaves, on every path. The Academic Vice Principal can raise the maximum; this is logged. Groups work the same way. |
| A transfer is saved at 11:00 "from today" after three lessons were marked. | The effective date is the first day in the new class, tomorrow by default. "Today" is allowed only if the student has no entries today in the old journals. |
| A transfer is recorded a week late. | Backdating is for the Academic Vice Principal, in an open quarter. Entries in the old journals on or after the date are listed; he either moves the date past them or voids them with a reason. They are never copied. In the new journal, cells of lessons already held open as optional: they do not change the lesson's status and can be filled for 7 days. |
| A transfer or a leaving is set for a future date. | It is "scheduled": the student shows the current class with a badge, and the seat in the target class is reserved. It can be changed or cancelled until the date. |
| A transfer was a mistake. | It can be undone only while the new journals hold no entries for the student. Otherwise a transfer back is made. |
| Two people move the same student at the same moment. | The second one gets "student changed, reload". |
| A student stopped coming on 1 October; leaving is recorded on 15 October. | The leave date is the last day as a student. Absences and zeros entered after it are voided: kept in history and removed from every figure. A "present" mark or a real score after the date blocks the save until someone checks it. A date in a closed quarter is refused. Open exemptions end and scheduled moves are cancelled. |
| A student returns. | In the same quarter and class: one row, with the gap closed. Into another class: handled like a transfer. In a later year: nothing is carried into the journals. Contracts are kept as a dated list, and a return adds a new one. A leaving entered by mistake has its own "undo leaving" action with a reason. |
| A student moves to another branch. | The sending Academic Vice Principal releases the student and the receiving one accepts, choosing class and groups; the Super Admin can do both. The record, UID, relatives and history stay the same and are readable in the new branch. |
| A student who left in 2025 is created again as new, or the name is typed Oʻtkir, O'tkir or Ўткир. | The duplicate check runs on every way of creating a student, across all branches, including inactive and graduated students. A matching JSHSHIR or document number blocks the save and offers "restore this student". A matching name and date of birth, compared after removing spelling differences, gives a warning that must be confirmed, so twins pass. The block and the warning name the matching student when they are in the same branch, and say "a student of another branch" otherwise. The Super Admin can merge two records; the older UID survives. |
| Release 1: UIDs are typed by hand. Two people type the same one, or one is mistyped. | Saving is refused if the UID is empty, does not fit the school's format, or already belongs to any student of any branch, including inactive and graduated ones; the message names that student when they are in the same branch, and says "a student of another branch" otherwise. When two people save the same UID at the same moment, the second is refused. A UID does not change when a student is promoted, transferred or returns, and is never given to another student. A mistyped UID can be corrected by the Academic Vice Principal with a reason; the old value stays in history. |
| Release 2: UIDs are taken from the set of the student's grade. | The Super Admin keeps the table of UID sets for the academic year (for example grade 7 is 2607XXX). When a student is created, the system takes the lowest free number in the set of the student's grade, in the same step as the save, so two students never receive the same one. A number that was used is never offered again, including numbers typed by hand earlier. When a set is full, the system says so and the UID is typed by hand. |
| A student is created twice by mistake. | The Academic Vice Principal may delete a student only if there is no attendance, number, exemption, result, scholarship, stipend entry or comment. Otherwise "leave" or the merge is used. |
| A student is graduated by mistake. | The Super Admin restores the student to active with a class and a reason. |
| The Tutor of a class changes in January, is ill, or the class has none. | The Tutor of a class is recorded with dates. The new Tutor sees the class's whole year; the earlier one loses access on the end date. An acting Tutor can be set for a period. A class with no Tutor shows a warning to the Academic Vice Principal and the Head Tutor. |
| Later, when an import is added: an Excel file with mixed date formats, phones as 9.989E+11, a class name typed with a Cyrillic letter, and the same student twice. | Only the system's template is accepted. Dates must be real dates or dd.mm.yyyy. Phones are converted to one format or the row fails. Look-alike Cyrillic and Latin letters in class and group names are treated as the same. Duplicates inside the file are errors. Confirming checks everything again and saves all rows or none. Uploading the same file again creates nothing. |
| Later, when an import is added: the same relative phone appears in the file under two names, or exists in the system under another name. | Both rows are errors until someone decides: link to the existing person, whose stored name is kept, or correct the phone. |
| A student left years ago and the profile still holds documents and phones. | Nothing is erased. The school keeps all data of a student who left, with no time limit, so the student can be brought back and old results can always be shown. |
