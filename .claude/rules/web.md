# Web app

Read `docs/spec/12-ux-standards.md` before building a new screen, and `docs/design-system.md` before building or changing any screen: its tokens, sizes and parts, and its list "What we never do".

- No hard-coded user-facing text. Add i18n keys in Uzbek, Russian and English together: the same key in `apps/web/src/i18n/locales/en.ts`, `uz.ts` and `ru.ts`. A text with a number has one key per plural form of its language (`_one`, `_other`; Russian also `_few`, `_many`). Uzbek is Latin script, with U+02BB in oʻ and gʻ. A missing key fails the type-check and `locales.test.ts`; the usual ways of writing a text into a component fail lint (what the rule cannot see is in `docs/decisions.md`, task 0.8a). A new component that takes a text under a property name of its own adds the name to `textAttribute` in `eslint.config.js`.
- A new error code of `packages/shared` needs its text under `errors` in the three files, written for the person: what happened and what to do next. Show a failed call with `failureText(t, error)` or `FailureAlert`; never show the `message` of the API.
- The text of an error code is true on every path of the API that sends it, as the person meets it there: a path where it would not be (a restore that refuses because of another record) gets a code of its own (found by the spec review of task 1.5). A constraint that guards several cases (one exclusion for the default, the weekdays and the grade ranges) is mapped to a specific code only where its text is true, and to the general refusal elsewhere (found by the review of task 1.5).
- Call the API only through the generated client, wrapped in `answerOf(...)` (`apps/web/src/api/failure.ts`), inside a TanStack Query or a mutation. A refusal that says the session ended or owes a step is handled for every call in `createShell`.
- A new page is a route in `apps/web/src/app/router.tsx`: inside `appRoute` when it needs a complete session. Nothing calls the API on a timer without asking: such a call counts as use of the session.
- Tests of a page render the whole app at its address with `renderApp` and `fakeApi` (`apps/web/src/testing/render-app.tsx`). Browser tests sign in with accounts of `apps/api/src/testing/e2e/seed.ts`, one account per test. Do not calculate results in the browser except by calling `packages/calc`.
- Follow the shared list, form and table patterns. Every screen has loading, empty and error states.
- A part that waits on a query tells loading from failure: `isError` shows `ErrorState` with a retry (or a short line where there is no room, as in the top bar), never the loading outline for good (found by the spec review of task 1.3 on the go-live section). A query that a field disables when it is empty counts too: a cleared field falls back to a value or says what to fill in (found by the spec review of task 1.5). So does a query that waits on a value from another query's answer (a date from `today`), and a part drawn with the data of a second query (the names of templates, the slot types of a panel): it shows the failure of either, with a retry, and never draws blanks or ids in their place (found by the reviews of task 1.5).
- A field whose options come from a query follows them: a choice kept in state falls back to an offered value when its own is no longer among them, so what the field shows is what it adds (found by the review of task 1.5).
- A list is a `ListPage` (`apps/web/src/components/list/list-page.tsx`): the feature gives the rows (`undefined` while loading), the columns, the filters, the bulk actions and the record for the side panel, and nothing draws a table, a search box or a checkbox column of its own. Its route has `validateSearch: listSearch` and hands the list `search` and `onSearchChange`. The sample is `apps/web/src/features/sample/sample-list-page.tsx` (`/dev/patterns` in development).
- A record form is `useRecordForm` with a schema of `packages/shared` and `RecordForm` (`apps/web/src/components/form/`), with the fields of `apps/web/src/components/field.tsx` (`Field`, `NumberField` read with `wholeNumber`, `SelectField`); nothing draws a Save button, a field message or a leave warning of its own. A form for another record gets a `key`. The sample is `apps/web/src/features/sample/sample-form.tsx`.
- An action that cannot be undone asks through `useConfirm()` (`apps/web/src/components/confirm-dialog.tsx`) and names what it will touch; a bulk action of a list gives `confirm`. Whatever takes a form away without a change of page asks `useLeave()` first (`apps/web/src/components/unsent/unsent-changes.tsx`).
- A dialog that sends something once (the feedback report, `apps/web/src/features/feedback/`) checks its field with `useRecordForm` and has a Send button of its own; it is not a record form: no `RecordForm`, no entry in the unsent store, and its typed text is kept in the tab while the dialog is closed.
- Colours come from the tokens of `index.css`. `tooling/contrast.test.ts` checks every text and control pair the components draw to WCAG 2.1 AA in both themes, with the alpha of the class list: a new token, or a component that draws text on a tint, adds its pair there. The theme is `useTheme()` and `ThemeSwitch`; nothing else reads or writes `sodiq.theme`.
- Text on screens (the owner's rule of 10 October 2026, issue #39): a page explains itself through its title and its content, not through a sentence under the title.
  - No intro paragraph on pages used every day (journal, timetable, lists, forms).
  - One short line only on an empty page (what it is for and the first action, `12` Look and feel), beside a switched-off action (why it is off) and under a setting whose effect is not obvious.
  - A menu page is a title and its links, with at most a few words under a link.
  - Never explain a field whose label already says it.
- A page inside the layout starts with `PageHeader` (title, breadcrumbs, actions). A part of a page that waits, is empty or failed uses `LoadingOutline`, `EmptyState` and `ErrorState` (`apps/web/src/components/states.tsx`); a failed call beside a form uses `FailureAlert`.
- An assertion on a text finds the element it is about (the cell of a row), never any element with the words: two keys with the same words in one language (a column header and a filter label) make such a test unable to fail (found by the review of task 1.5).
- A test of a page with a long table reads rows from the table itself (`document.querySelectorAll('tbody tr')`): a query by role over hundreds of rows takes seconds in jsdom. A filter, an order and an opened record come from the address, which changes a moment after the click: wait for them.
- The menu hides what a role cannot use, but never rely on that for safety: the server decides.
- Content on the grey canvas sits in a white panel (`PANEL` of `apps/web/src/components/ui/control.ts`: no border, no shadow); a bordered box is drawn only inside a panel. A link is `text-link`, weight 600, underlined on hover; a field, select, checkbox and focus outline take `FIELD`, `Select`, `CHECKBOX` and `FOCUS_RING` (found by the spec review of task 2.2d-1).
- A test that reads the sources for a forbidden prop value matches every way of writing it: an attribute, a value chosen inside braces, an object key and a default value (found by the spec review of task 2.2d-1).
